# ERR-002 · CI android-check：移动目标 C 依赖交叉编译（openssl-sys 找不到 OpenSSL）

- **日期**: 2026-09-26
- **模块**: `.github/workflows/ci.yml`（android-check 作业）/ src-tauri 依赖图
- **现象**: `cargo check --target aarch64-linux-android --locked` 在 GitHub Actions 失败（exit 101）。
- **复现步骤**: push master → 观察 CI android-check 作业（仓库私有无 API 权限，靠 Annotation + `ci-logs-android` artifact 排障）。
- **已试方案**（aws-lc-sys 错误类，2 次额度已用）：
  1. 尝试 1（811bf9a）：NDK cmake 工具链显式化 → 仍报 cc-rs 找不到裸名 `aarch64-linux-android-clang`。
  2. 尝试 2（7215b60）：显式 `CC_aarch64_linux_android`/`AR`/`CARGO_TARGET_..._LINKER` 指向 NDK API-24 clang wrapper + bin 入 `GITHUB_PATH` → **aws-lc-sys 已通过**（编译推进到 openssl-sys）。
- **当前错误（新错误类，openssl 首次出现）**: `openssl-sys v0.9.117` build script 退出 101——Android 目标无系统 OpenSSL，pkg-config 不支持交叉，`OPENSSL_DIR/LIB_DIR/INCLUDE_DIR` 全未设置。
- **根因**: `git2 https` feature → `libgit2-sys` → `openssl-sys`（仅 unix 目标；Windows 走 WinHTTP 不受影响，本地 Windows 开发从未暴露）。Android/iOS 无系统 OpenSSL，必须 vendored 源码编译（add-cicd-multiplatform design.md L71 已预判此风险）。
- **依赖链证据**: `cargo tree -i openssl-sys --target aarch64-linux-android` → git2 0.20.4 + libgit2-sys 0.18.8；同命令 `--target x86_64-pc-windows-msvc` → 图中无此 crate。
- **候选路线**:
  - A（推荐）: target-gate 直依赖 `openssl-sys = { features = ["vendored"] }`（android/ios/macOS），Cargo.lock 新增 `openssl-src`（源码编译 OpenSSL 3.x）——依赖白名单扩展，需用户批准 + ADR。
  - B（降级）: 移动端砍 git2 https/push（git2 改桌面 target-gate）——产品能力降级 + 规格矛盾，须用户拍板。
- **状态**: ✅ 已解决（2026-09-26 用户批准路线 A 含 macOS：vendored openssl，`openssl-src 300.6.1+3.6.3` 入锁，ADR-005 落账；同轮定位 Linux sync_engine 失败为另一根因 ERR-003）
