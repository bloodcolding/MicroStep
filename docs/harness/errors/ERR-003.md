# ERR-003 · CI Linux sync_engine 14 例失败：gix reflog 无 committer 身份

- **日期**: 2026-09-26
- **模块**: src-tauri/src/data_dir.rs（git 骨架）/ sync_engine（gix fetch/push ref 更新）
- **现象**: CI Linux `cargo test --test sync_engine` 14 例失败，两类错误串：`Git("The reflog could not be created or updated")` 与 `Network("Failed to update references to their new position to match their remote locations")`（后者为 gix fetch receive 的 ref 更新失败，被 classify_transport 归为 Network）。
- **排障路径**:
  1. 尝试 1（7215b60）：假设为 logs/ 目录树缺失 → 补齐骨架目录 → **无效**（CI 复跑同样 14 例失败）。
  2. 读 gix-ref 0.67.1 源码定位错误串出处：`transaction/commit.rs` `Error::CreateOrUpdateRefLog`，其 source 被外层 `to_string()` 吞掉；内因枚举中 `MissingCommitter` 与现象吻合（`reflog_create_or_append` 在 `committer.ok_or(Error::MissingCommitter)?`）。
  3. 链路证据：`gix::Repository::reference()` → `edit_references` → `edit_references_as(edits, self.committer()?)`；`fetch update_refs` 同样调 `repo.committer()`。committer 从 config user 身份解析，无身份返回 None。
  4. 环境差异实锤：本机 `~/.gitconfig` 有身份（测试全绿）vs CI 全新 runner 无任何 git 身份。
- **本地复现（关键验证）**: 隔离 `HOME`/`USERPROFILE` 至空目录（钉住 `CARGO_HOME`/`RUSTUP_HOME` 防工具链失效）后 `cargo test --test sync_engine` → **同样 14 例失败、同错误串**；修复后同环境 19/19 全绿。
- **根因**: 无全局 git 身份的环境（CI 全新 runner、未安装/未配置 git 的终端用户）下 gix ref 事务写 reflog 缺 committer 签名。产品级缺陷：AppData 骨架仓库不应依赖用户侧 git 配置。
- **修复**: 骨架 config 内置 `[user]` 同步身份 + 存量自愈（ADR-006）；tc_i26 断言 + tc_i29 自愈回归。
- **状态**: ✅ 已解决（2026-09-26，2 次尝试额度内）
