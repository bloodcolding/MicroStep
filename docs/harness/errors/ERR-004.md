# ERR-004 · WebView2 154 + --remote-debugging-port 启动期 IPC 竞态（CDP 冒烟悬挂）

- **日期**: 2026-10-11 ~ 2026-10-12
- **模块**: 前端冒烟基建（WebView2 CDP 通道）
- **状态**: ✅ 已绕过（隔离 identifier 全新 profile + 探活重试循环；根因属 WebView2/Tauri 环境交互，未修产品代码）

## 现象

带 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222"` 启动 Tauri 应用后，前端首个 IPC（`get_meta`/`get_state`）的 **promise 永不结算**：`todayLabel` 已渲染（DOMContentLoaded 完成）、无任何异常/控制台输出、Rust 侧命令已执行（stderr 可见），但响应回不到 JS。无该环境变量时应用完全正常（UIA 无障碍树 200 元素、真实档案完整渲染）。

## 根因定性（排除法 + 决定性对照）

- WebView2 Evergreen **154.0.4258.62**（i18n 冒烟 09-25 时 36/36 正常，之后 WebView2 自动更新）+ Tauri 2.11.6 + `--remote-debugging-port` 三者组合的**启动期偶发竞态**。
- 旧 WebView2 profile（`%LOCALAPPDATA%\com.microstep.app\EBWebView`）上近乎必现（10-11 ~ 10-12 约 0/15+ 成功，仅一次侥幸）；**全新 profile（临时 identifier `com.microstep.smoketest`）下稳定健康**（3/3 一次通过）。
- 与前端代码无关：纯基线（HEAD）同样悬挂；曾误判 viewport-fit=cover / styles.css / ui.js 为元凶，均为竞态假阳性。

## 排障中踩的两个坑（引以为戒）

1. **GUI 子系统进程 + 未重定向 stderr 时 `eprintln!` 会 panic**（句柄 NULL → 写失败 → Rust eprintln panic → 异步 command 崩溃 → invoke 无响应）。给 `get_meta` 加 AGENT-DEBUG eprintln 后，所有未重定向启动的 bisect 全部"悬挂"——调试注入本身成了混淆变量。GUI 进程调试输出必须 `-RedirectStandardError`。
2. **`%APPDATA%` 环境变量重定向对 Tauri `app_data_dir()` 无效**：`dirs`/Tauri 走 Windows Known Folder API（SHGetKnownFolderPath），忽略环境变量。隔离数据目录必须改 identifier（或显式路径参数）。

## 绕过方案（已验证）

1. 临时将 `tauri.conf.json` identifier 改为 `com.microstep.smoketest` → cargo build（数据与 WebView2 profile 全新目录，双隔离）。
2. 重试循环：带端口启动 → CDP 读 `#simpleSanHint` 探活（非空 = 该实例 IPC 健康）→ 健康实例立即跑完整冒烟脚本；最多 6 次（实测全新 profile 第 1 次即健康）。
3. 冒烟后还原 identifier、清理 `com.microstep.smoketest` 目录（Roaming + Local）。
